# M1 数据文件保存权限问题 — 审计报告

**状态：仅调查，未修复。**  
**日期：** 2026-11-14  
**范围：** M1 数据/密钥文件“另存为”到 Windows 桌面时出现「你没有权限在此位置中保存文件」。

---

## 1. 问题描述

用户在 M1 页编辑数据后点击保存，选择 Windows 桌面作为目标位置，Windows 弹出：

> 你没有权限在此位置中保存文件。

需区分的可能：是否只影响桌面、是否只影响覆盖、是否仅某个账户/环境、是否软件缺陷、是否系统策略。本报告只给出证据与排序，不实施修复。

## 4. 错误提示产生位置

**关键结论：用户看到的提示不是本软件输出的。**

| 证据 | 内容 |
|---|---|
| 源码检索 | 整个 `src/`、`i18n/` 中不存在「你没有权限在此位置中保存文件」或等价的 `permission` 提示 |
| 软件实际提示 | 成功路径无提示；失败路径为 `tr("Failed to save to")`（中文“无法保存至”+ 路径） |
| 日志 | 失败时会写 `Failed to save: <path>`（`eMRTD/FileIO` 模块名），可用日志区分 |
| 文案来源 | 该中文文案是 Windows 资源管理器/通用保存对话框在目标位置不可写时的系统提示 |

因此该弹窗发生在 **Qt 调用原生保存对话框期间或系统写入检查阶段**，而不是 `data_saveDataFile()` 的 `QMessageBox`。若 `data_saveDataFile()` 返回 false，界面显示的是“无法保存至”，与用户描述不同。

## 5. Qt API 使用情况

| 项目 | 现状 | 审计结论 |
|---|---|---|
| 对话框 | `QFileDialog::getSaveFileName(...)` 静态函数，未传 `options` | 使用 Windows 原生对话框（默认） |
| 默认目录 | `"./data_" + defaultName`（相对当前工作目录） | 非桌面；对话框打开位置取决于上次使用位置/当前目录 |
| 覆盖行为 | `QFile::open(WriteOnly)` | **截断打开**：若写入中途失败，原文件已被清空（潜在数据丢失） |
| 原子性 | 未使用 `QSaveFile` | 无临时文件 + commit 机制 |
| 错误信息 | 只返回 bool | 丢失 `errorString()`/错误码，无法区分“权限/占用/空间/路径无效” |
| 覆盖只读文件 | 未预先检查文件属性 | 只读文件会失败，但错误被统一成“无法保存至” |
| 扩展名 | 仅由过滤器决定 | 用户可输入任意扩展名 |
| 失败后数据 | 编辑内容仍在内存 | 不会丢数据，但无“另存为其他位置”引导 |

### 已确认的软件缺陷（与本次弹窗无关）

1. 写入失败统一提示“无法保存至”，不显示 `QFile::errorString()`，无法区分权限/占用/空间/路径。
2. `QFile::open(WriteOnly)` 截断原文件，写入失败可能造成原文件内容丢失。
3. 未使用 `QSaveFile`，无原子提交。
4. 默认保存目录为相对 `./`，依赖进程工作目录（发布目录），与用户预期桌面无关。
5. 不校验扩展名、不预检目标文件只读/占用。

### 7.6 关键系统证据（2026-11-14 追加）

工作区目录 `E:\Opencode_project` 的 ACL 与普通用户目录明显不同：

```text
E:\Opencode_project
    Everyone:(CI)(DENY)(DC)
    S-1-4-640475301-819002524:(OI)(CI)(W,D,DC)      ← 非标准 SID，被授予写/删除
    NT AUTHORITY\Authenticated Users:(I)(OI)(CI)(F)
    NT AUTHORITY\SYSTEM:(I)(OI)(CI)(F)
    BUILTIN\Administrators:(I)(OI)(CI)(F)
    BUILTIN\Users:(I)(OI)(CI)(F)
    Mandatory Label\Low Mandatory Level:(OI)(CI)(NW)  ← 低完整性标签
```

对比：

```text
C:\Users\van\Desktop
    SYSTEM / Administrators / van : FullControl (继承)
C:\Users\van
    ... S-1-15-3-65536-...:(S,X)                      ← 能力 SID，仅读/执行
```

解读：

- `S-1-4-640475301-819002524` 是非标准（沙箱/受限令牌）SID，**只在工作区被授予写权限**；
- 工作区被标记为 **Low 完整性**（`NW`），与普通用户目录（Medium）不同；
- 桌面/用户目录没有任何此类 SID 的写授权，也没有 deny ACE、所有者正常（`van`）。

这与用户现象完全吻合：**进程以“受限令牌/沙箱身份”运行，只有当目标目录的 ACL 显式授予该身份写权限时（即工作区）才能保存**；桌面等目录没有该授权，于是 Windows 保存对话框报“无权限”，并提议改存到用户文件夹。

因此：

- 这不是文件只读、占用、ACL 损坏或 M1 保存代码的问题；
- 任何软件侧改动（`QSaveFile`、默认目录、错误提示）都不会改变该结果；
- 需要处理的是**启动方式/沙箱/应用控制策略**（使进程以普通 `van` 令牌运行），而不是修改程序。

### 7.8 追加现象（2026-11-14）

| 测试 | 结果 |
|---|---|
| 弹窗选择“是（改存到 van 文件夹）” | **仍然失败** |
| 以管理员身份运行后另存到桌面 | **成功** |

这组结果的含义：

- 失败与目标目录无关（桌面、用户根目录都失败），只与**进程是否提升**有关；
- 提升后的进程使用未过滤的链接令牌（High 完整性、无写限制），因此可以正常写入；
- 非提升进程的令牌被施加了**写限制**（Write-Restricted Process 语义），只有当目标目录显式授予其受限 SID 时才允许写入——工作区正是如此（`S-1-4-640475301-819002524`）；
- 桌面与用户目录只授予 `SYSTEM / Administrators / van`，没有该受限 SID，所以非提升进程一律被拒。

补充检查（只读）：

- `HKCU/HKLM ...\AppCompatFlags\Layers` 中**没有** `Proxmark3GUI.exe` 条目（不存在 RunAsLowIL / RUNASADMIN 兼容层）；
- 桌面与用户目录**没有显式完整性标签**（默认 Medium）；
- 注册表中存在与本程序无关的 `WRPMitigation` 条目（其他程序），说明本机确实使用过 WRP 机制。

### 7.9 结论修正

原因不是“目录权限”，而是 **非提升进程的令牌被写限制**（受限 SID 只授予了工作区）。  
该限制由**启动方/安全策略**施加，不是程序自身、不是 ACL、不是只读/占用。

重要：**“以管理员身份运行”只作为证据，不作为建议方案**。本阶段明确不以管理员运行作为绕过手段，也不修改任何系统权限或安全配置。

## 10. 结论

- 用户看到的「你没有权限在此位置中保存文件」**不是本软件生成的文案**，而是 Windows 保存对话框/系统写入检查的提示；软件自身的写入失败提示是“无法保存至”。
- 现象链完整：桌面失败、用户根目录也失败、改名无效、与覆盖/只读/占用/管理员权限无关；**普通程序写桌面正常**；**以管理员身份运行时可以保存**。
- 造成该现象的是**针对 `Proxmark3GUI.exe` 施加的写限制**：仅工作区 `E:\Opencode_project` 被授予写权限（ACL 中存在非标准 SID `S-1-4-640475301-819002524` 的写授权 + Low 完整性标签），桌面/用户目录没有该授权；非提升进程被限制，提升后绕过。
- 机器上运行的安全软件为 **Huorong Internet Security**（`HipsDaemon`、`HRWSCCtrl` 正在运行），未发现其它 AV/EDR；该现象与火绒的 **HIPS/自定义防护规则**（按程序限制文件写入范围）一致，是最可能的施加者。
- 已排除：程序自身的保存实现、目录 ACL 异常、只读/占用、管理员权限缺失、压缩包运行、助手会话沙箱（非管理员双击仍失败）。
- 因此软件侧的任何改动（`QSaveFile`、错误提示、默认目录）**都不会消除该现象**。
- 现有代码仍存在可改进点（截断写入、错误信息粗糙、无 QSaveFile、默认目录相对路径），建议在权限问题定位后作为独立的健壮性改进处理。
- **不采用“以管理员身份运行”作为长期方案**（安全风险，且掩盖真实原因）。应在火绒中确认/调整针对该程序的规则，或由用户决定是否信任该程序。

**本阶段未修改任何 M1 保存相关代码、未修改系统权限或安全配置、未在真实桌面写入测试文件。**
